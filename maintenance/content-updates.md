# 대시보드 변경 영향 확인

설계 내용은 기존 JSON에만 둔다. `docs/data/freshness.json`은 페이지별 원본 목록, 내용 해시, 페이지 갱신 시각과 연관 검토 영수증만 저장한다. 외부 라이브러리는 사용하지 않는다.

## 매 갱신 작업의 순서

1. 수정 전 `node scripts/content-freshness.mjs --status`를 실행하고 대상 페이지의 `updatedAt`, `reviewedAt`, `reviewNote`를 읽는다. 진행 중인 다른 변경과 이미 검토가 필요한 페이지를 확인한다.
2. 표제어·설계 원본을 수정한다. 새 이름과 옛 이름, ID를 저장소 전체에서 검색해 `related`, 본문 참조, 사건 순서, 세계시간·개인시간, 그림 노드·선, 개요, 미정 사항까지 확인한다. 명시적 연결 없는 의미 관계도 사람이 찾는다.
3. `node scripts/content-freshness.mjs --sync-index`로 제목·요약·분류를 원본과 맞춘다. 목차에만 있던 옛 별칭은 보존한다. 본문과 다른 별도 요약을 목차에 직접 쓰지 않는다.
4. `node scripts/content-freshness.mjs --status`의 **모든 영향 페이지**를 읽는다. 원본을 수정했으면 2–3단계를 반복한다. 연대표는 목록뿐 아니라 `worldchronology`, `personal-order`, `flow.nodes`, `flow.edges`를 대조한다. 배열 순서가 공개 순서인지 실제 발생 순서인지 임의로 추정하지 않는다.
5. 페이지별로 `node scripts/content-freshness.mjs --review story/wiki/chronology "수정: 사건 설명과 흐름도 반영 / 이미 일치: 개인시간 / 미정: 발신 시점 유지"`처럼 실제 확인 결과를 기록한다. 변경 불필요일 때도 구체적 이유를 적는다. 일괄 자동 승인이나 날짜만 올리는 스크립트는 금지한다. `--review`는 한 페이지만 받는다.
6. `node scripts/content-freshness.mjs --check`와 `node --test test/*.test.mjs`를 통과시킨다. UI 변경 시 캐시 버전 및 실제 화면을 확인한다. PR에는 연관 반영 결과와 남은 미정 사항을 명시한다.

## 시각과 검증의 의미

- **페이지 갱신**: 해당 페이지의 직접 데이터·렌더러·공통 UI 파일 중 가장 최근 변경 시각. 초기 값은 Git 커밋 시각에서 얻으며 정확한 설계 결정 시각을 뜻하지 않는다. 미커밋 수정은 검토 시각을 사용한다.
- **연관 검토**: 연결된 원본과 함께 내용을 확인한 실제 시각. 내용 변경이 없어도 검토 후 갱신할 수 있다. 과거 검토를 증명할 수 없으면 `null`이며 화면에 ‘기록 없음’으로 표시한다.
- 화면은 KST로 표시한다. 브라우저 로컬 초안에는 저장소 기록을 적용하지 않는다.
- CI는 날짜의 앞뒤 대신 입력 해시와 참조 목록을 비교한다. 동일 초의 변경도 검토를 무효화한다. 렌더러 import를 따라가고, 위키의 명시적 ID·링크·related 및 제목/별칭 언급을 직접 참조로 수집한다. Story 목차와 Open Questions도 위키 변경의 영향 대상으로 둔다.
- 직접 참조 검사는 의미 일관성 증명이 아니다. 암시적 관계, 관계 자체의 누락, 확정/제안/미정 승격과 서사 인과는 사람이 검토한다. 다른 페이지 내용을 추가 수정하면 다시 영향 검사를 수행해 다음 단계로 전파한다.
- 첫 도입의 해시 기준선은 과거 전체 검토를 주장하지 않는다. 초기 `reviewedAt`은 비워 두고, 이후 실제 검토한 페이지만 기록한다. 기준선 재초기화는 CLI에서 거부한다.
- 새 최상위 화면·데이터 원본을 추가하면 `collectPages()`의 소유 원본 매핑과 회귀 검사를 함께 갱신한다. 이미지 자체의 픽셀 수정과 코드 밖의 암시적 데이터 읽기는 별도 점검 대상이다.
